kavier-perf — inference

Replay a request trace through a discrete-event, KV/prefix-cache-aware serving simulator. This is the inference CLI; for fine-tuning steps, see kavier-train.

For each request in the trace, kavier-perf simulates a prefill stage (encoding the prompt) and a decode stage (autoregressive generation), tracking KV-cache memory and an optional cross-request prefix cache. It reports per-request latency, throughput and GPU utilisation — the metrics that matter for serving, not training.

Flags & options

Flag / OptionTypeDefaultDescription
--llmstrLlama-3-8BKey of the LLM to simulate (see LLM_SPEC_LIBRARY).
--gpustrA10GPU model (see GPU_SPEC_LIBRARY).
--tracepathsrc/data/input/input_example.csvInput trace containing per-request token counts (CSV or Parquet).
--output_folderpathsrc/data/outputDestination directory for generated Parquet files & summary.
--kv_cacheon | offonEnable/disable vLLM-style KV caching.
--export_ratefloat0.1Snapshot interval in seconds for utilisation traces.
--flush_sizeint1000Rows to buffer before writing Parquet (0 → one-shot).
--prefix_cache_min_tokensint1024Minimum prompt length (tokens) required to enter the prefix cache.
--max_cached_promptsint10Capacity of the prefix cache (LRU).
--cache_scopesession | globalsessionWhether the cache key includes session_id.
--prefix_cache_policynone | prefill | fullprefillprefill: skip prefill on hit. full: skip prefill and decode.

LLM and GPU names must match keys in the library, e.g. LLMs Llama-3-8B, mistral-7b-v0.1, granite-3.3-8b, mixtral-8x7b-instruct-v0.1; GPUs A10, A100-80GB, H100-SXM, L40S.

Example: smallest

kavier-perf --trace src/kavier_inference/data/input/input_example.csv

Example: medium

kavier-perf \
  --llm         Llama-3-8B \
  --gpu         A10 \
  --trace       traces/your_workload.csv \
  --kv_cache    on \
  --export_rate 0.1 \
  --flush_size  1000

Example: full

kavier-perf \
  --llm                     Llama-3-8B \
  --gpu                     A10 \
  --trace                   traces/workload.csv \
  --output_folder           results/run-01 \
  --kv_cache                on \
  --export_rate             0.05 \
  --flush_size              1000 \
  --prefix_cache_min_tokens 1024 \
  --max_cached_prompts      10 \
  --cache_scope             session \
  --prefix_cache_policy     prefill

Input trace format

The trace is a CSV (or Parquet) with one row per request:

ColumnRequiredMeaning
num_input_tokensyesPrompt length (tokens).
num_output_tokensyesGenerated length (tokens).
session_idoptionalGroups requests for --cache_scope session.
input_tokens / output_tokensoptionalActual token id lists, if available.

Output

Each run writes a timestamped folder under --output_folder containing tasks.parquet (one row per request, with a duration latency in ms and a total_tokens column for efficiency) and fragments.parquet (GPU-utilisation snapshots every --export_rate seconds). An OpenDC-compatible workload is also exported for downstream sustainability. A summary is printed to stdout (not a file):

note

The bundled --trace default in argparse points at src/data/input/…, which may not exist in a fresh checkout. Use the shipped example path above (src/kavier_inference/data/input/input_example.csv) or your own trace.
