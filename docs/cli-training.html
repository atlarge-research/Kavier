kavier-train — fine-tuning

An analytical model of one fine-tuning step. Predicts step throughput, runtime, MFU and GPU power for a single config — or every row of a CSV.

Unlike the discrete-event inference simulator, kavier-train evaluates a closed-form model: it sums the forward pass, backward pass, optimizer update and (multi-GPU) gradient all-reduce into a step time, then derives throughput and runtime. It supports full, lora and gptq-lora methods, and its predictions are calibrated against a real fine-tuning trace (see Core formulas and the validation note).

Simulate every row of a CSV

kavier-train --input_csv src/kavier_training/data/input/input_example.csv

Each row supplies a full config (model_name, method, gpu_model, tokens_per_sample, batch_size, number_gpus, number_nodes). The CLI prints one line per row with tokens/sec and runtime, then a count of rows simulated.

Flags & options

Flag / OptionTypeDefaultDescription
--input_csvpath(unset)Simulate every row of this CSV instead of a single config.
--model_namestrrequired*Key of the model to simulate.
--methodfull | lora | gptq-lorarequired*Training / fine-tuning method.
--gpu_modelstrrequired*GPU model key, e.g. NVIDIA-A100-SXM4-80GB.
--tokens_per_sampleintrequired*Sequence length — tokens per sample.
--batch_sizeintrequired*Samples per GPU per step.
--number_gpusintrequired*GPUs per node.
--number_nodesintrequired*Number of nodes (total GPUs = number_gpus × number_nodes).
--total_tokensint(unset)Total tokens to train over, used to estimate full runtime.
--opendc_output_dirpath(unset)If set, export an OpenDC-compatible workload to this directory.
--opendc_task_idint0Task id used in the OpenDC export.
--opendc_submission_time_msint0Submission time (ms) used in the OpenDC export.

* Required for single-config runs; alternatively pass --input_csv to simulate every row of a CSV.

tip

train_runtime is 0 unless you pass --total_tokens (the dataset size to train over). Without it you still get per-step throughput, MFU and power.

Single-config example

kavier-train \
  --model_name mistral-7b-v0.1 \
  --method lora \
  --gpu_model NVIDIA-A100-SXM4-80GB \
  --tokens_per_sample 1024 \
  --batch_size 4 \
  --number_gpus 8 \
  --number_nodes 1 \
  --total_tokens 100000000

Output

A single-config run prints a header and a JSON object:

{
  "train_tokens_per_second": 18452.7,
  "train_tokens_per_gpu_per_second": 2306.6,
  "train_samples_per_second": 18.02,
  "train_steps_per_second": 0.563,
  "train_runtime": 5419.3,
  "model_name": "mistral-7b-v0.1",
  "gpu_name": "NVIDIA-A100-SXM4-80GB",
  "method": "lora",
  "batch_size": 4,
  "tokens_per_sample": 1024,
  "number_gpus": 8
}

Internally the step model also computes gpu_compute_utilization (MFU %), gpu_memory_utilization and gpu_power_watts — the power figure (OpenDC's MSE model) is what kavier-co2 consumes. A --input_csv run instead prints a one-line-per-row table and a final count. With --opendc_output_dir it also exports an OpenDC-compatible workload.

On bad or missing arguments

If required flags are missing, the CLI prints a ready-to-run example command to copy.
