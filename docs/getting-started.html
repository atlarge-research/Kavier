Getting started

In this mini-tutorial, we will show how to get started with Kavier in under 10 minutes.

1. Pre-requisites

  1. Python >= 3.11 (required by pyproject.toml)
  2. pip >= 23 & virtualenv / venv
Tip for Apple Silicon

brew install python@3.11

2. Clone & create a virtual environment

git clone https://github.com/<you>/kavier.git
cd kavier

python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
python -m pip install -U pip

3. Install Kavier

pip install -e ".[dev]"

This resolves runtime deps (pandas, pyarrow, numpy, …), registers editable packages so edits in src/ apply instantly, and installs the CLI entry points:

  • kavier-perf — inference simulation
  • kavier-train — fine-tuning (training) prediction
  • kavier-energy — efficiency per million tokens (alias: kavier-eff)
  • kavier-co2 — emissions against a carbon trace

4. Run your first simulation

4.1 The bundled trace

A tiny inference trace ships at src/kavier_inference/data/input/input_example.csv. Or bring your own — the columns are:

  • [REQUIRED] num_input_tokens — input tokens in the request
  • [REQUIRED] num_output_tokens — output tokens in the response
  • [OPTIONAL] session_id — session id (used by --cache_scope session)
  • [OPTIONAL] input_tokens / output_tokens — actual token-id lists

4.2 Your first simulation

kavier-perf --trace src/kavier_inference/data/input/input_example.csv

4.3 Your first output

A timestamped folder appears under --output_folder with two Parquet files, plus an OpenDC-compatible export; a readable summary prints to your terminal.

  • tasks.parquet — one row per request (latency, total_tokens, …)
  • fragments.parquet — GPU-utilisation snapshots
  • a SIMULATION SUMMARY table on stdout (prefill/decode time, p95 latency, cache hit ratio)
Milestone

Congrats — you just ran your first Kavier inference simulation!

5. A typical inference run

kavier-perf \
  --llm         Llama-3-8B \
  --gpu         A10 \
  --trace       src/kavier_inference/data/input/input_example.csv \
  --kv_cache    on \
  --export_rate 0.1 \
  --flush_size  1000

See the Inference CLI for all flags.

6. Predicting a fine-tuning job

Training is a separate analytical model — no trace, just a config:

kavier-train \
  --model_name mistral-7b-v0.1 --method lora \
  --gpu_model NVIDIA-A100-SXM4-80GB --tokens_per_sample 1024 \
  --batch_size 4 --number_gpus 8 --number_nodes 1

It prints a JSON object with tokens/sec, MFU and power. See the Training CLI.

7. OpenDC sustainability

Kavier integrates with the peer-reviewed OpenDC for sustainability. After an inference run, feed the exported workload through OpenDC (see its docs) to produce a powerSource.parquet — no manual conversion needed.

8. Post-processing: efficiency metrics

With a tasks.parquet (from Kavier) and a powerSource.parquet (from OpenDC):

kavier-energy \
  --kavier src/data/output/<TIMESTAMP>/tasks.parquet \
  --opendc /path/to/powerSource.parquet \
  --price  10            # optional GPU-hour price → enables the $ metric

Sample output (all metrics per million tokens, lower is better):

----------  Efficiency summary  ----------
   energy_efficiency (Wh/Mtoken): 84.5
 carbon_efficiency (gCO2/Mtoken): 39.0
 financial_efficiency ($/Mtoken): 2.36
                    total_tokens: 1234567
------------------------------------------

For time-and-grid-aware emissions instead, see kavier-co2.

9. Running the test-suite & linters

pytest -q          # the math has tests
ruff check .       # style & import order
mypy .             # static typing (strict)

10. Troubleshooting

SymptomFix
ModuleNotFoundError for kavier.*Make sure the venv is active and you ran: pip install -e ".[dev]"
Mypy says a file is "found twice"Import modules with the kavier. prefix, not a relative path.
  • Did you find a bug? Please open an issue!
  • Did you do any error that others might do? Let us know and we'll add it to this list! See contributing guidelines.

11. Next steps

  1. Plug in your own traces (CSV / Parquet with token counts) for inference.
  2. Tune cache policies – try --prefix_cache_policy full vs prefill.
  3. Sweep training configs with kavier-train --input_csv to compare GPUs, methods and batch sizes.
  4. Read the Core formulas to see exactly what each engine computes.
