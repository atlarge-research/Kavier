two predictors · one library
Scientific instrument for LLM ecosystems

Kavier — predict the performance, sustainability & efficiency of LLM workloads.

Two distinct predictors share one GPU/LLM library: a discrete-event inference simulator for serving, and an analytical training model for fine-tuning steps.

Get started → Inference Training

Two predictors, kept separate

Kavier is a research tool from AtLarge Research and IBM for sizing LLM workloads before you run them. Inference and training are different problems, so Kavier keeps them in separate engines:

Inference
kavier-perf — replays a request trace through a discrete-event, KV/prefix-cache-aware simulator. Predicts prefill & decode latency, p95, throughput, cache hit ratio.
Training
kavier-train — an analytical model of one fine-tuning step (forward + backward + optimizer + all-reduce). Predicts step throughput, runtime, MFU, GPU power.

Both feed two sustainability tools that reuse OpenDC's power model: kavier-energy (efficiency per million tokens) and kavier-co2 (emissions against a carbon-intensity trace).

The four CLIs

kavier-perf

Inference

Discrete-event, cache-aware serving simulator. Replays a request trace to predict prefill/decode latency, throughput and GPU utilisation.

Read the reference → kavier-train

Training

Analytical fine-tuning model. Predicts step throughput, runtime, MFU and power for one config — or every row of a CSV.

Read the reference → kavier-energy

Efficiency

Combines a tasks.parquet with OpenDC's powerSource.parquet into energy, carbon and (optional) cost per million tokens.

Read the reference → kavier-co2

CO2

Walks a workload's power profile through a carbon-intensity trace (gCO2/kWh) to estimate total emissions, per time window.

The library feeds both engines; calibration applies to training only. The inference engine can also export an OpenDC-compatible workload; OpenDC's powerSource.parquet then flows into kavier-energy.

What it has been validated against

The analytical training model is the one with published accuracy numbers. On the held-out 15% test split of a ~30k-run IBM fine-tuning profiling dataset (PD1 / Sfttrainer), and for the specific models and GPUs it was calibrated on:

~6.2% MdAPE
calibrated training model (throughput & runtime), down from ~15% uncalibrated.
~0.8ms
to make 100 training predictions — fast enough for million-point grid sweeps.
≈0Δ
power vs. OpenDC's MSE model (Kavier reuses it), at ~24,000× the speed.
honest caveat

These figures are for the analytical training model, measured on one held-out test set and a fixed set of models/GPUs — they are not a universal accuracy guarantee, and the inference simulator is not validated with the same MdAPE study. Treat predictions as planning estimates, not ground truth.

Structure

Source lives under src/, one package per concern:

src/
├── kavier_inference/   # discrete-event inference simulator (kavier-perf, kavier-eff)
├── kavier_training/    # analytical fine-tuning model    (kavier-train)
├── kavier_energy/      # efficiency per million tokens   (kavier-energy)
├── kavier_co2/         # emissions vs. carbon trace      (kavier-co2)
├── kavier_library/     # shared GPU & LLM specifications
├── kavier_opendc/      # OpenDC workload export (tasks/fragments)
├── kavier_io/          # shared I/O utilities
└── tests/              # test suites

Quick start

git clone https://github.com/<you>/kavier.git
cd kavier

python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
python -m pip install -U pip
pip install -e ".[dev]"

Run your first (inference) simulation:

kavier-perf --trace src/kavier_inference/data/input/input_example.csv

That writes Parquet artifacts and prints a summary. See Getting started for the full tour.
